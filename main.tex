\section{Preliminar Assumptions}

All the experiments were made using the Kaggle platform. The experiments were run using two GPU T4, each one with 15GB of capacity. There were used some external input files: 1. "Boccaccio": sentences from famous operas (Boccaccio's "Decameron" and "Il Filocolo") dated back to the same period of the dataset given for testing. These sentences have been manually translated with the competence that ensures no translation errors in the training dataset's "Gold Reference". This dataset consists of 18 "big" sentences that were the most etherogeneus possible, with the scope to give the model the power to translate various archaic italian styles (since the testing dataset is made by sentences in various archaic styles). "Decameron" ensures a mixture of styles and having different "social levels" dialogues. "Il Filocolo" instead has a more scientific style, tones are more aulic and syntax is more correct, helping the model to better understand the syntax but also the semantics of "base" archaic words and sentences. 
2. "Dante": A csv file, containing the famous "Divine Comedy"

3. "Test Dataset Augmmented": The test dataset augmented with the manual (human) "Golden Translation", for each testing sample.
4."Human Scores": Both the models' translations of the testing dataset manually annotated with the quality score of each model translation (1 to 5), for each testing sample, using the same metrics to assign a score as the "Score Rubrics" used in the section "LLM as a judge". 

\section{Fine Tuning an LLM}
The first techninque adopted to achieve the goal was to fine tune a medium sized LLM, using as training dataset "Boccaccio" and perform the translations with the In Context Learning technique.
The model selected for this scope is "Mixtral-8x7B-Instruct-v0.1": the Mistral 8x7B LLM fine tuned via SFT and DPO on istruction following. The choice of an Istruct model was made by different aspects: 1. The istruct models are more able to follow precisely the istructions given in the prompt, since the prompt for inference is augmented with the in-context learning technique and a detailed instruction. 2. Less data needed as training to have quality results: since the dataset "Boccaccio" is made only by 18 sentences, there is needed a model capable to learn "quicker" than the base models. 3. It is more adapt to learn from prompts structured as the training process was built: Istruction ("Sei un esperto linguista ... ") + Input $\rightarrow$ Gold Output. The loading process in GPU memory was made by a 4 bit quantization process of the Hugging Face model, to fit the 30GB memory capacity. The model took in total around 24GB in inference mode and 14,5GB in training mode, since the training was performed using only one of two GPU and the model training was performed with a prevoius "LoRA" adaptation to reduce the training parameters to 3,407,872 (0.0073\% of the total). The traslations were performed with an In-Context Learning prompt technique, to reinforce the power of the Instruct model to learn from small samples, even without fine tuning. The translations produced good quality results, in fact they were inserted into a file and evaluated by a human using the same evaluation method as the section "LLM as a judge", resulting in an average of 3,49 for the 97 test samples.

\section{Considerations}
Starting from a manual evaluation of both the model translations and from the average human score for them, it is clear that the Mistral fine tuning method was the most efficient one. One of the reasons could be that Machine Translation models could be very good in word per word translation, but not as able as medium/big LLMs to capture the context and the semantics of the whole sentence and are less able also to translate into coherent sentences starting from a new language without a fine tuning using huge datasets and lots of epochs. The judgments with LLMs confirms this opinion, having analysed both the LLM scores but also their text feedbacks.

\section{LLM as a judge} 
There were performed different evaluations of the translation of both the techniques: 1. "Gemini as Judge": the evaluation was performed through API calls to the Google model "gemini-2.5-flash". The prompt was built using the "Prometheus" template for judging, with custom imstructions, Rubric Scores explanations and scores from 1 to 5. The "Gold Reference" was taken from the "Test Dataset Augmmented" dataset. The average score over the Mistral traslations was 3,29 so very close to the human average. The average score over the Opus traslations was 2,19, the same of the average for human (2,2). 2. "Prometheus as Judge": to perform this evaluation technique, it was loaded a 4 bit quantized version of the model "Unbabel/M-Prometheus-7B" since it is the multilingual version of "Prometheus‑7B" and it was more suitable to italian. The model used 7,5GB of GPU memory. The prompt was built in the standard Prometheus format customized (the same prompt of the method 1).


\section{Agreement LLM with human scores} 
The judgments were compared to the human judgments, for both the models. There were calculated the Cohen's Kappa coefficients over the Prometheus judgments for both the models: default (no weights, each error is considered in equal way), linear weights, quadratic weghts. The most suitable coefficent for this scope was thought the quadratic weights one, since it increases quadratically as the absolute difference of scores, taking more into account serious judgment errors rather than LLMs scores that are closer to the human ones. The quadratic Cohen's Kappa coefficient for the Opus model translations was 0.0332, meaning a very huge disappointment betweeen judgments even if the average was similar. The answer could be due to a lot of "small distance errors", but the judgments could be considered acceptable in average. The quadratic coefficient for Mistral was 0.1614, confirming what deduced with the Opus coefficient and the hypothesis of the subsection "Considerations".
